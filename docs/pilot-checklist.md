# Human pilot checklist

Planning: 4–6 separate pilot volunteers; this is a feasibility plan, not a validated sample for an effect. Record which stage each volunteer completed. Include fresh volunteers in the silent rehearsal. Software checks cannot replace either stage.

## Stage 1 — usability walkthroughs

- [ ] Unfamiliar volunteers explain the checking sequence, packaging rules, category/judgment/Submit/Finish distinction, and automatic secondary-task return in their own words.
- [ ] Observe searching, ambiguous comparisons, confusion, accidental finishes, duplicate activations, and comprehension of “Response recorded.” Check both return states and whether the factual card is understood without suggesting it should help.
- [ ] Inspect instructions, demonstration, corrective practice feedback, ordinary work, B return, C return, questionnaire and completion on the target workstation. Verify all task controls and records fit at 1280×720 CSS pixels with readable text, visible focus and no scrolling. Record browser version, OS, physical display, scaling, CSS viewport, browser zoom and mouse/trackpad setup.
- [ ] Check 200% zoom and narrow reflow: no lost controls or horizontal text clipping; unsupported timed configurations are recorded/paused. Restore the supported setup for timed rehearsal. Test fresh pointer/keyboard action after real returns, including held keys and double clicks.
- [ ] Record issues and revise consistently. **Think-aloud timings are not experimental performance data.** Recheck all affected behavior after a change and issue a new version for scientific changes.

## Stage 2 — silent protocol rehearsal

- [ ] Use the finalized interface and script, including fresh volunteers. Run complete sessions silently, without coaching about next checks.
- [ ] Check training sufficiency, attempts/failures and explanation consistency; everyone experiences all three demonstration configurations. Do not weaken the criterion per participant.
- [ ] Check actual interruption exposure and engagement, early answers, omissions, cue visibility/removal, record continuity and stable B/C geometry.
- [ ] Examine matched-set difficulty, sequence/judgment errors, unobserved expected checks, floor/ceiling effects, carryover, total visit length, workload completion and comfort.
- [ ] Verify complete exports: exact manifests, raw events, all submitted checks, episodes, item exposure, rating wording/anchors, null reasons, denominators, disruptions and session versions. Recompute from raw events and compare. Check offline retry and saved completion in a synthetic run.
- [ ] Document findings and release decision before main collection. If the clear baseline has little resumption burden, report it and discuss the study design. Do not obscure controls, tune using emerging main effects, silently add complexity, or seek a significant C advantage.

## Pilot-4 observations to record

- [ ] Timing budget: consent/instructions, each demonstration, each assessed attempt, each block, ratings, fixed/additional breaks, overall duration. Target 20–25 minutes; no time pressure or exclusion at 25 minutes.
- [ ] Distinguish corrected wrong selections, out-of-sequence submissions, factual judgment errors, intentional revisits, premature finishes and missing opportunities. Ask about intent after the visit, without changing the recorded endpoint.
- [ ] Inspect each of the six return positions (after 2–7 submissions); whether participants anticipate one interruption/order; eight-row readability and reserved card visibility.
- [ ] Inspect error-rate floor/ceiling and denominator loss, not a significance test of the cue. Four to six volunteers cannot establish power or equal difficulty. Record unexpected interpretations and discuss endpoint validity before main collection.
