# Export dictionary · hmc-metrics-1

ZIP contains UTF-8 CSV tables plus `bundle.json` (canonical structured values) and `manifests.json`. Empty CSV numeric cells mean unavailable, never zero. JSON booleans retain type. CSV nested fields contain JSON. Free-text cells beginning with spreadsheet formula characters are prefixed with an apostrophe; JSON retains originals. Time intervals are **milliseconds**; server receipt/creation fields are UTC ISO 8601. Block positions are 1–3. Order indices are 0–11; human-readable fixture IDs are 1–12. Allocation slots and batches are zero-based.

- **sessions**: anonymous ID, protocol, mode, synthetic marker, lifecycle status, last acknowledged sequence, creation UTC, exclusion status. Credentials are never exported. Status is the latest lifecycle state; raw events retain when consent, training, block starts, completion, or withdrawal happened.
- **allocations**: permanent slot, cycle, batch, condition permutation, temporal task-set permutation, B secondary form. C uses the other form. Seed and schedule identifier are in the session's protocol manifest. Slots are never recycled. Unassigned sessions have no row.
- **raw_events**: event UUID, session, sequence, document segment, performance.timeOrigin (`origin`, epoch ms), monotonic `mono` ms, type, event-specific payload, server UTC receipt, and server-derived context. Context contains protocol/build/metrics versions, condition, block, task set, order index, practice flag, expected category before event, actual last category, cue state, and input method. A block_start context describes the pre-transition state; its block identifies the new block. Each document begins with a document event. Allocation is authoritative in the allocations table.
- **practice_attempts**: attempt number, start/end sequences, submission count, and exact comprehension responses. An interrupted attempt retains a null ending.
- **orders**: one attempted order per block; completed flag, correct final judgments, fixed denominator 4, omissions, duplicate submissions, sequence-error events, and missed scheduled checkpoint with reason. An unfinished exposed order is retained but does not enter completed-order accuracy. Missing unexposed orders are not fabricated.
- **checks**: category, attempt count, first/final boolean judgment, first/final correctness, omission and completed-order flags. Each required category has a row, including omissions. Raw events preserve every intermediate attempt.
- **interruptions**: B/C only; ID is checkpoint event UUID. Start/return within segment, actual secondary interval, expected category at return, sequence-deviation flag, technical flag, recovery observation and reason, observation-window end, first action latency/error, first submission latency/category/correctness, secondary form and engagement. Main A checkpoints remain invisible raw ack_end events with checkpoint=true; no A recovery latency is calculated.
- **questionnaires**: block/condition and three deliberate integer ratings, custom-workload-1. Wording and anchors are in each manifest. Not a validated workload instrument.
- **summaries**: participant × block × condition; order, task set, previous main cue exposure, universal practice cue exposure, eligible/observed/unobserved/flagged/valid recovery counts, observed mean/median, elapsed/active time, secondary/pause/combined union durations, completed orders, accuracy numerator/denominator, omissions, duplicates, sequence errors, workload. Unfiltered latency summaries include flagged observations; inspect flags. Main task sequence errors count selection and submission events separately, not unique error episodes.
- **quality**: conservative document/pause/resume flags, with sequence, block, order, segment and reason. Reloaded blocks have null elapsed/active duration: clocks are never subtracted across documents. Segment-specific interruption durations may remain available.
- **annotations**: immutable researcher notes, quality reviews and exclusions, with author and UTC timestamp. An exclusion does not delete observations. The deployment has one researcher role, so author is `researcher`; use separately authenticated deployments if named individual attribution is required.
- **audit**: relevant issuance, rejection, protocol and annotation actions. Rejections do not enter the accepted behavioral stream.

The latest derived materialization is stored in SQLite with metrics version and through-sequence; every export recomputes it from raw records. Manifests contain all exact realized fixtures, independent answer keys, schedule, secondary forms, configuration snapshot and application build identifier. Protocol version is a mandatory analysis grouping field.

## Timing definitions

Recovery = first selection of the category that was expected at return minus return. Earlier wrong actions do not reset the clock. Judgment correctness does not determine recovery. When that selection never happens, recovery stays null; reasons distinguish no remaining check, order ending, incomplete session, or clock discontinuity. Window-end times include their own segment field. First action includes Finish order; it is an error if checks remain. Recovery is not a content-solving time.

Elapsed block time runs from block_start availability to final Finish order. Active time subtracts the union of actual secondary and technical pause intervals. Overlapping pauses count only once. Recovery and 300 ms acknowledgements remain in active time. Questionnaires and inter-block breaks are outside the block window. Partial blocks are marked incomplete and have null full-block elapsed/active values.

`quality=clean` on export adds a sensitivity table with only technically uncompromised recoveries that had no pre-existing sequence deviation, and recomputed recovery counts/means/medians. Original interruption and summary tables remain intact. This predefined filter does not filter on outcome or accuracy. Nulls and exclusions are never converted to zeros. Default main export excludes synthetic/demo/pilot sessions. Withdrawal/exclusion rows remain in raw tables but their derived analysis rows are omitted unless `include_excluded=true`. This is retention, not erasure; communicate this policy during consent.
